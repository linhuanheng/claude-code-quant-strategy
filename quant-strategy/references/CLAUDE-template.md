## 一、核心设计原则（不可违反）

### 原则 1：禁止引入未来信息（Look-ahead Bias）

在任意时间点 `t` 的计算，**只能使用时刻 `t` 及之前已知的信息**。这是本项目的最高原则，违反它的回测结果在实盘中毫无意义。

#### 1.1 因子标准化
- **禁止**：对全时间序列做 `df.mean()` / `df.std()` 后对整列做 z-score
- **必须**：使用 `df.rolling(window=252).mean()` / `.std()`，或 expanding window
- **代码示例**：
  ```python
  # 正确：PIT 标准化
  rolling_mean = factor.rolling(window=252, min_periods=63).mean()
  rolling_std = factor.rolling(window=252, min_periods=63).std()
  zscore = (factor - rolling_mean) / rolling_std
  ```

#### 1.2 分位数分组
- **禁止**：`pd.qcut(factor, q=5)` 作用在全量 DataFrame 上（相当于已知未来排序）
- **必须**：每期截面独立计算分组，用 `df.apply(lambda row: pd.qcut(row, q=5, labels=False), axis=1)`

#### 1.3 财务数据披露延迟
- **禁止**：直接将财务报告的 `end_date`（报告期）当作数据可用日期
- **必须**：年报 +4 个月（4/30 前）、中报 +2 个月（8/31 前）、季报 +1 个月后才视为可用
- **实现方式**：使用 `disclosure_date` 字段或 `f_ann_date` 字段，而非 `end_date`

#### 1.4 信号执行时点
- **禁止**：T 日收盘生成信号 → T 日收盘价执行（这是前视，因为收盘价和信号同时产生）
- **必须**：T 日收盘生成信号 → T+1 日开盘价（`open`）或 T+1 日 VWAP 执行

#### 1.5 ML 模型训练
- **禁止**：`train_test_split(shuffle=True)`、`KFold`（随机交叉验证）、全样本标准化后切分
- **必须**：按时序切分，使用 `TimeSeriesSplit`，walk-forward 方式，训练集标准化参数应用于验证/测试集，训练集与测试集之间至少间隔 1 个持仓周期（purge-embargo）

#### 1.6 因子筛选
- **禁止**：在全样本上计算因子 IC/ICIR，选出"好因子"后再回测
- **必须**：IC/ICIR 用滚动窗口计算，因子筛选发生在回测循环内部，每期只使用到当期为止的信息

#### 1.7 停牌/ST/退市处理
- **禁止**：回测开始时一次性剔除所有"曾经 ST / 曾经退市"的股票
- **必须**：每期根据当期已知的上市状态过滤（当日是否 ST、是否停牌、是否已退市）

### 原则 2：收益分析规范

每次向用户汇报策略收益分析结果时，以下内容**缺一不可**：

#### 2.1 收益分布统计（必须全部汇报）
| 统计量 | 含义 |
|--------|------|
| Mean | 均值 |
| Median | 中位数 |
| P5 | 5% 分位数 |
| P25 | 25% 分位数 |
| P40 | 40% 分位数 |
| P75 | 75% 分位数 |
| P95 | 95% 分位数 |

策略收益、基准收益、超额收益三者都需要汇报。日度/周度/月度均可，但必须标注周期。

#### 2.2 显著性检验
- 对超额收益（alpha）做 t 检验
- **必须同时汇报 OLS t 值和 Newey-West 自相关稳健 t 值**，使用 `statsmodels.stats.sandwich_covariance.cov_hac`
- NW 滞后阶数：L = ⌊4 × (T/100)^(2/9)⌋
- Bartlett 核权重
- p 值标注显著性：\*\*\* p<0.01, \*\* p<0.05, \* p<0.10

#### 2.3 经自相关调整的夏普比率
- 年化夏普比率：Sharpe = (mean(r) - rf) / std(r) × √252
- 自相关调整（Lo 2002 方法）：Sharpe_NW = Sharpe / √(1 + 2 × Σ ρ_k)，Bartlett 权重 w_k = 1 - k/(L+1)

## 二、子 Agent 使用规范

本项目包含两个专用子 Agent，它们的指令文件位于 `sub-agent/` 目录。主 Agent 必须严格遵守以下调用规范。

---

### Agent A：Look-ahead 审计 Agent（前置关卡）

**指令文件**：`sub-agent/lookahead-auditor.md`

**职责**：回测和收益分析的**双重前置关卡**。审查代码中是否引入了未来信息（7 类前视偏差）。只读代码、报告违规，不修改代码。

#### 触发时机（强制执行）

以下任一情况发生时，**必须先启动审计 Agent，审计通过后才能继续**：

| 触发场景 | 审计范围 |
|---------|---------|
| 代码发生改动后，用户要求运行回测 | 变更文件 + 受影响的调用链文件 |
| 用户要求查看收益分析 / 回测结果 / 绩效表现 | 涉及收益计算的全部 `.py` 文件 |
| 用户要求核对策略表现 | 策略模块 + 回测模块 + 分析模块 |
| 项目初始化生成全部代码后 | 所有生成的文件 |
| 用户说"帮我检查有没有未来信息" | 用户指定范围或全部文件 |

**绝对禁止**：
- 代码改动后未经审计，不得运行回测
- 审计通过之前，不得向用户展示任何收益数字、分布统计、显著性结果、净值曲线

#### 调用方式

使用 Agent 工具，参数如下：
- `subagent_type`: `"general-purpose"`
- `description`: `"Look-ahead audit"`
- `prompt`: 指定审计 Agent 读取 `sub-agent/lookahead-auditor.md`，并列出待审计的文件路径

#### 审计结果处理

- **违规数 = 0（通过）**→ 向用户报告"审计通过，未发现前视偏差"，然后展示分析结果
- **违规数 > 0（未通过）**→ 逐条向用户说明每项违规的类型、位置、影响、修复方案 → 修复 → 重新审计 → 通过后方可展示结果
- **多次修复仍未通过**→ 请用户介入决策

#### 审计 Agent 检测的 7 类违规

| # | 违规类型 | 严重程度 |
|---|---------|---------|
| 1 | 全样本标准化（用全序列均值/std 做 z-score） | 高 |
| 2 | 全样本分位数分组（用全序列分位点分组） | 高 |
| 3 | 财务数据披露延迟忽略 | 中 |
| 4 | T 日收盘价用于 T 日决策 | 中 |
| 5 | ML 训练数据泄漏（shuffle、随机 CV） | 高 |
| 6 | 因子筛选使用全样本统计量 | 高 |
| 7 | 停牌/退市/ST 信息前视 | 低-中 |

### Agent B：开发日志 Agent（全程记录）

**指令文件**：`sub-agent/dev-logger.md`

**职责**：忠实记录开发过程中每次改动的细节。只追加记录，不评价改动。

#### 触发时机（操作后调用）

以下操作完成后**必须调用日志 Agent 追加记录**：

| 触发操作 | 记录内容 |
|---------|---------|
| 创建或修改 `.py` 文件 | 文件名、改动内容摘要 |
| 修改 `config.py` 参数 | 参数名、旧值 → 新值 |
| 运行回测 | 回测时间范围、主要绩效数字（年化收益、夏普、最大回撤） |
| 审计 Agent 检查完成 | 审计结论（通过 / N 项违规） |
| 修复前视偏差 | 修复了哪几项违规、怎么修复的 |
| 用户提出新策略想法并落实 | 策略变更摘要 |
| 数据源变更 | 之前用哪些、现在用哪些 |

#### 调用方式

使用 Agent 工具，参数如下：
- `subagent_type`: `"general-purpose"`
- `description`: `"Dev log record"`
- `prompt`: 指定日志 Agent 读取 `sub-agent/dev-logger.md`，并提供本次改动的描述（时间戳由日志 Agent 自动生成）

#### 日志格式

日志保存在项目根目录 `DEV_LOG.md`，每条记录包含：序号、时间戳（精确到分钟）、改动类型、涉及文件、改动摘要、改动详情、结果、备注。

### Agent 协同工作流

```
用户发出指令
      │
      ├──→ 涉及代码改动？ ──→ 主 Agent 执行改动
      │         │
      │         └──→ 改动完成 → 调用日志 Agent 记录
      │
      ├──→ 涉及运行回测？
      │         │
      │         └──→ 调用审计 Agent 审查（代码改动后必须审计）
      │               ├── 通过 → 运行回测 → 调用日志 Agent 记录
      │               └── 不通过 → 修复 → 重审
      │
      ├──→ 涉及收益分析/回测结果展示？
      │         │
      │         └──→ 调用审计 Agent 审查
      │               ├── 通过 → 展示结果
      │               │         └──→ 调用日志 Agent 记录
      │               └── 不通过 → 修复 → 重审
      │                            └──→ 调用日志 Agent 记录
      │
      └──→ 项目初始化？
                │
                └──→ 生成代码 → 调用审计 Agent
                      ├── 通过 → 告知用户
                      └── 不通过 → 修复 → 重审
                      └──→ 调用日志 Agent 记录
```

**核心约束**：审计在前，回测在后；审计在前，结果在后；操作完成，日志跟随。

## 三、开发流程

### 日常开发
1. 策略逻辑写在 `strategy/base.py` 中，继承 `BaseStrategy`，实现 `generate_signal(date, data)` 方法
2. 配置参数在 `config.py` 的 `StrategyConfig` 中修改
3. 因子定义在 `factors/builder.py` 中添加
4. 运行 `python main.py` 执行完整回测

### 修改代码后
1. 调用日志 Agent 记录本次改动
2. 如果改动涉及计算逻辑，调用审计 Agent 审查
3. 审计通过后再运行回测
4. 展示收益分析结果前，再次确认审计已通过

### 查看结果前
1. 确认审计 Agent 已对当前代码执行且通过
2. 分析结果必须包含完整的收益分布（7 项分位数）、OLS + NW t 检验、NW 调整夏普
3. 展示绩效表和 5 张必选图表

## 四、关键约束速查
- 执行价格：T+1 开盘价（`next_open`）
- 手续费：双边万三（0.03%）+ 千一卖出印花税（0.05%）
- 滑点：1bp（0.01%）
- 涨停不买，跌停不卖，成交量 = 0 不交易
- 停牌股票：当日不调入，已持仓的按 0 收益处理
- 财务数据：使用最新公告日可用的数据，非报告期数据
- 复权方式：后复权（`adj_factor` 修正）
- 最小交易单位：100 股
- 无风险利率：2%（可配置）
- 审计通过是展示收益结果的前提条件
- 所有开发操作后必须调用日志 Agent 记录
